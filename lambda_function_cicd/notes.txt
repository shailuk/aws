GitHub Actions OIDC -
  1) How it works in simple terms.
  2) Request a Token: When your workflow starts, GitHub issues a temporary, short-lived security token.
  3) Exchange: Your workflow sends this token to AWS.
  4) Validate: AWS looks at the token and says, "I recognize this token came from Shailesh's specific GitHub repository and branch."
  5) Grant Access: AWS gives your workflow temporary credentials that expire automatically after the job finishes.

  1) Go to IAM -> Identity providers -> Create provider
      Provider Type: OIDC
      Provider URL: https://token.actions.githubusercontent.com
      Audience: sts.amazonaws.com
      Enter your github organization name and repo name(Optional)

  2) Create a Role for OIDC
      Go to IAM -> Roles -> Create Role
      Select "Web Identity" as the trusted entity type
      Choose the OIDC provider you created in step 1
      Set the audience to sts.amazonaws.com
      Attach the necessary permissions - AWSLambdaFullAccess
      Name the role (e.g., GitHubActionsServiceRole)
      Create the role and note down the ARN for use in your GitHub Actions workflow

  3) Make sure the ARN is updated in your deploy.yml file for the "Configure AWS Credentials" step and the "Deploy to AWS Lambda" step.
